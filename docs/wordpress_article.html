Managing files on an SD card connected to an Arduino often means physically removing the card, plugging it into a computer, and copying files back and forth. This process can be tedious, especially for projects mounted in enclosures or hard-to-reach places. But what if you could manage those files remotely, over your local network, just like you would with a web server? That's exactly what the SimpleFTPServer library enables.

In this tutorial, I'll guide you through setting up a fully functional FTP server on an Arduino UNO or Mega using a standard W5500 Ethernet shield and a MicroSD card. We will use the excellent SdFat library for robust and high-performance SD card access, which is a must for serious projects.

Why an FTP Server on Your Arduino?

The primary advantage is remote file management. Imagine your Arduino is serving a web page from an SD card. If you want to update the HTML, CSS, or JavaScript files, you would typically have to take the system offline. With an FTP server, you can:

  • Upload new web pages or data files directly to the SD card.
  • Download data logs or sensor readings that your Arduino has been collecting.
  • Delete old files or rename them without physical access.
  • List the contents of the SD card to check its status.

This is incredibly useful for IoT projects, data loggers, and any application where the Arduino needs to work with files that change over time.

Hardware and Software Prerequisites

  • An Arduino UNO or Mega. The Mega is recommended for its larger memory, which is helpful for network applications.
  • A W5100 or W5500 Ethernet Shield with an integrated MicroSD card slot, OR standalone Ethernet and SD modules.
  • A formatted MicroSD card (FAT32 is best).
  • An Ethernet cable and a connection to your router.
  • Arduino IDE installed on your computer.

Library Installation

You'll need three libraries for this project. You can install all of them through the Arduino IDE's Library Manager (Sketch -> Include Library -> Manage Libraries...):

  1. SimpleFTPServer: Search for "SimpleFTPServer" and install the library by me, Renzo Mischianti.
  2. SdFat: Search for "SdFat" by Bill Greiman and install the latest version. This is a much more powerful and reliable alternative to the standard SD library.
  3. Ethernet: This library is usually pre-installed with the Arduino IDE, but ensure it's up to date.

Configuration: SD vs. SdFat and FtpServerKey.h

The SimpleFTPServer library is highly configurable through the FtpServerKey.h file, located inside the library's folder. This file allows you to select the filesystem, network interface, and other core settings without modifying the library's source code.

Choosing a Filesystem: SD vs. SdFat

For Arduino UNO and Mega, you have two primary choices for SD card access. The choice has significant implications for performance and memory usage.

The Standard SD Library

  • Pros: It's bundled with the Arduino IDE and uses slightly less RAM and program memory. This can be a critical advantage on an Arduino UNO, where memory is extremely limited (only 2KB of RAM).
  • Cons: It is significantly slower, less reliable, and, most importantly, only supports 8.3 filenames (e.g., MYFILE.TXT). Long filenames are not supported, which is a major limitation for modern use cases like web servers.

The SdFat Library

  • Pros: It is the modern, high-performance standard. It's much faster, more reliable, supports long filenames, and has better error handling.
  • Cons: It uses more RAM and program memory than the standard SD library.

Recommendation:

  • On an Arduino Mega, always use SdFat. The performance benefits are significant, and the Mega has enough RAM to handle it comfortably.
  • On an Arduino UNO, the choice is a trade-off. If your project is very simple and you are running out of RAM, the standard SD library might be necessary. However, for any serious application, it's worth trying to optimize your code to free up enough memory for SdFat.

How to Configure the Library

To switch between filesystems, you need to edit FtpServerKey.h. You can find this file inside your Arduino libraries folder (e.g., Documents/Arduino/libraries/SimpleFTPServer/FtpServerKey.h).

Open the file and find the section for Standard AVR Arduino configuration:

// In FtpServerKey.h

// Standard AVR Arduino configuration
#ifndef DEFAULT_FTP_SERVER_NETWORK_TYPE_ARDUINO
	#define DEFAULT_FTP_SERVER_NETWORK_TYPE_ARDUINO 	NETWORK_W5100
// Change this line to switch between SD and SdFat2
// 	#define DEFAULT_STORAGE_TYPE_ARDUINO  STORAGE_SD // Standard, low-RAM, 8.3 filenames only
	#define DEFAULT_STORAGE_TYPE_ARDUINO  STORAGE_SDFAT2 // Recommended, high-performance, long filenames
#endif

To use the standard SD library, comment out STORAGE_SDFAT2 and uncomment STORAGE_SD:

#define DEFAULT_STORAGE_TYPE_ARDUINO 			STORAGE_SD

Remember, after changing this, you must also update your sketch to include the correct header (#include <SD.h>) and use the correct object (SDClass sd;).

Wiring and Connections

Both the Ethernet chip and the SD card communicate using the SPI protocol, so they share the MISO, MOSI, and SCK pins. However, they must have separate Chip Select (CS) pins.

Using an Ethernet Shield

This is the easiest setup. Simply stack the Ethernet shield onto your Arduino. The shield is designed to handle the connections automatically.

  • The W5x00 Ethernet chip uses pin 10 as its Chip Select (CS).
  • The SD card slot on the shield almost always uses pin 4 as its Chip Select (CS).

Using Standalone Modules

The Code

Here is the complete sketch to get the FTP server running. I've added detailed comments to explain each part of the code.

/*
 * SimpleFTPServer on Arduino Mega/UNO with W5500 Ethernet and SdFat
 * Author: Renzo Mischianti
 * Website: www.mischianti.org
 *
 */

#include <SPI.h>
#include <Ethernet.h>
#include <SdFat.h>
#include <SimpleFTPServer.h>

// --- Network Configuration ---
// Enter a MAC address for your controller below.
// Newer Ethernet shields have a MAC address printed on a sticker.
byte mac[] = { 0xDE, 0xAD, 0xBE, 0xEF, 0xFE, 0xED };
// Set the static IP address to use if the DHCP fails to assign
IPAddress ip(192, 168, 1, 177);

// --- SD Card Configuration ---
// The Chip Select pin for the SD card on most Ethernet shields is 4.
const int SD_CS_PIN = 4;
// The Chip Select for the Ethernet controller is 10.
const int ETH_CS_PIN = 10;

// --- Object Instances ---
SdFat sd;
FtpServer ftpSrv;

void setup() {
  Serial.begin(115200);
  while (!Serial) {
    ; // wait for serial port to connect. Needed for native USB port only
  }
  Serial.println("FTP Server starting...");

  // Disable the SD card while initializing Ethernet
  pinMode(SD_CS_PIN, OUTPUT);
  digitalWrite(SD_CS_PIN, HIGH);

  // --- Initialize Ethernet ---
  Serial.println("Trying to get an IP address using DHCP");
  if (Ethernet.begin(mac) == 0) {
    Serial.println("Failed to configure Ethernet using DHCP");
    // Try to configure using static IP address instead:
    Serial.print("Setting static IP to: ");
    Serial.println(ip);
    Ethernet.begin(mac, ip);
  }

  Serial.print("FTP Server IP address: ");
  Serial.println(Ethernet.localIP());

  // --- Initialize SD Card ---
  // It's crucial to initialize the filesystem AFTER the network.
  Serial.print("Initializing SD card...");
  if (!sd.begin(SD_CS_PIN)) {
    Serial.println("Initialization failed!");
    Serial.println("Things to check:");
    Serial.println("* is a card inserted?");
    Serial.println("* is your wiring correct?");
    Serial.println("* did you change the chipSelect pin to match your shield or module?");
    while(1); // Halt execution
  }
  Serial.println("SD card initialized.");

  // --- Start FTP Server ---
  // The credentials are "arduino", "arduino"
  ftpSrv.begin("arduino", "arduino");
  Serial.println("FTP Server started!");
}

void loop() {
  // It's important to let the Ethernet library maintain its connection.
  // This is especially important for W5500 shields.
  Ethernet.maintain();

  // This is the most important part. It handles all incoming FTP client requests.
  // Make sure to call this in every loop.
  ftpSrv.handleFTP();
}

Connecting with an FTP Client

1. Open your favorite FTP client (FileZilla, WinSCP, etc.).
2. Open the Serial Monitor in the Arduino IDE to see the IP address assigned to your device.
3. In your FTP client, enter the following:

  • Host: The IP address of your Arduino (e.g., 192.168.1.177).
  • Username: arduino (or what you set in the code).
  • Password: arduino.
  • Port: 21.

Click connect, and you should see the contents of your SD card's root directory! You can now drag and drop files to upload or download them, create directories, and manage your device's storage remotely.

Library API Reference

The SimpleFTPServer library is more than just a basic file server. Let's look at its main functions.

Core Functions

// Constructor
FtpServer(uint16_t cmdPort = 21, uint16_t pasvPort = 50009);

// Start with username and password
void begin(const char* user, const char* pass, const char* welcomeMessage = "Welcome");

// Start in anonymous mode
void begin(const char* welcomeMessage = "Welcome");

// Stop the server
void end();

// Main handling function (call in loop)
uint8_t handleFTP();

// Set a static IP for the server to report in PASV mode
void setLocalIp(IPAddress localIp);

// Change credentials after starting
void credentials(const char* user, const char* pass);
  • FtpServer(...): The constructor. You can optionally specify the command port (default 21) and the passive data port (default 50009).
  • begin(user, pass, ...): Starts the FTP server with mandatory authentication. You can also provide an optional welcome message.
  • begin(welcome_message): An overload that starts the server in anonymous mode (no login required).
  • handleFTP(): This is the engine of the server. It must be called in every loop() to process incoming client commands and manage data transfers.
  • end(): Stops the FTP server and disconnects any active client.
  • setLocalIp(...): Use this if your device is behind a NAT and you need to specify a public IP for passive mode.
  • credentials(...): Allows you to change the username and password while the server is running.

Callback Functions for Advanced Control

Callbacks allow your sketch to react to FTP server events in real-time. This is incredibly powerful for monitoring, debugging, or triggering other actions.

Connection Status Callback

The setCallback() function registers a function to be called whenever a client connects, disconnects, or a file operation changes the available disk space.

// Define the callback function
void ftpCallback(FtpOperation ftpOperation, unsigned int freeSpace, unsigned int totalSpace) {
  switch (ftpOperation) {
    case FTP_CONNECT:
      Serial.println("FTP Client connected!");
      break;
    case FTP_DISCONNECT:
      Serial.println("FTP Client disconnected!");
      break;
    case FTP_FREE_SPACE_CHANGE:
      Serial.print("FTP Free space changed: ");
      Serial.print(freeSpace);
      Serial.print(" / ");
      Serial.println(totalSpace);
      break;
  }
};

// In your setup()
ftpSrv.setCallback(ftpCallback);

Transfer Status Callback

The setTransferCallback() function is even more detailed. It lets you monitor the progress of file uploads and downloads, which is perfect for providing feedback, like blinking an LED during a transfer.

// Define the callback function
void ftpTransferCallback(FtpTransferOperation ftpOperation, const char* name, unsigned int transferredSize) {
  switch (ftpOperation) {
    case FTP_UPLOAD_START:
      Serial.print("FTP Upload started: ");
      Serial.println(name);
      break;
    case FTP_UPLOAD:
      Serial.print("FTP Uploading: ");
      Serial.print(name);
      Serial.print(" -> ");
      Serial.println(transferredSize);
      break;
    case FTP_DOWNLOAD_START:
      Serial.print("FTP Download started: ");
      Serial.println(name);
      break;
    case FTP_DOWNLOAD:
      Serial.print("FTP Downloading: ");
      Serial.print(name);
      Serial.print(" -> ");
      Serial.println(transferredSize);
      break;
    case FTP_TRANSFER_STOP:
      Serial.print("FTP Transfer stopped: ");
      Serial.println(name);
      break;
    case FTP_TRANSFER_ERROR:
      Serial.print("FTP Transfer error: ");
      Serial.println(name);
      break;
  }
};

// In your setup()
ftpSrv.setTransferCallback(ftpTransferCallback);

Advanced Usage: Remote Firmware Updates

One of the most powerful applications of an FTP server is for remote firmware updates (Over-the-Air or OTA updates). The process involves uploading a compiled firmware file (a .bin file) to the SD card via FTP, and then triggering the Arduino to flash itself with the new firmware.

While a full OTA implementation is beyond the scope of this article, the concept is straightforward and builds directly on the server we've just created. I've written a detailed guide on this topic that you can follow as a next step: How to update firmware via FTP (OTA) on ESP8266 and ESP32. Although the article focuses on ESP boards, the core principles can be adapted for AVR boards like the Mega using a suitable bootloader (e.g., Optiboot with SD support).
